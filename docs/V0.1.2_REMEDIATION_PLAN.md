# v0.1.2 Remediation Plan

This plan defines the work required to turn the reviewed
`v0.1.2-candidate` changes into a mergeable `v0.1.2` release. The current
candidate is not merge-ready.

## Decision

Create `release/v0.1.2` from `main` and reapply the approved changes as
independent, reviewable commits. Do not merge `v0.1.2-candidate` as a unit.

This avoids carrying the stacked and misleading scope of PR #5, keeps each
hardware behavior change bisectable, and permits the two diagnostic accessors
to be left out of the patch release.

## Pull Request Inventory

### PR #4

[PR #4](https://github.com/photon-circus/ph-esp32-mac/pull/4) contains one
commit:

- Correct MDIO output-enable routing.
- Add an EMAC DPORT reset pulse during initialization.

The PR description matches its four changed files, but it presents the reset
sequence as equivalent to ESP-IDF without noting ESP-IDF's RCC atomic section.

### PR #5

[PR #5](https://github.com/photon-circus/ph-esp32-mac/pull/5) is described as
an esp-hal 1.1 interrupt API port, but its five commits also contain:

- `rx_debug()` public API.
- Receive Buffer Unavailable interrupt enablement.
- `mac_debug()` public API.
- MAC address register write reordering.

These are independent public API and hardware behavior changes. The PR has no
review discussion and no CI evidence, so its summary must not be used as the
release scope.

## Behavior Impact

| Change | `main` behavior | Candidate behavior | Risk |
|--------|-----------------|--------------------|------|
| MDIO output enable | MDIO is held on the software output-enable path; reads can return the controller's driven value instead of PHY data. | EMAC controls MDIO direction and can release the line for PHY read data. | Low after on-device validation; directly affects PHY discovery and link state. |
| EMAC peripheral reset | Initialization enables the clock without the vendor reset pulse. | Every `Emac::init` asserts and deasserts EMAC reset before later configuration. | High until atomicity and lifecycle are resolved; reset is global hardware state. |
| esp-hal 1.1 binding | Fresh dependency resolution can select esp-hal 1.1 while the integration calls removed 1.0 APIs. | Uses `bind_handler`, preserving bind-and-enable behavior on the registering core. | Medium; feature wiring and the exact-1.0 downstream compatibility boundary are undocumented. |
| RBUE interrupt | RX complete, TX complete, summaries, and fatal bus error are enabled; no RX-buffer-unavailable wake is generated. | RX-buffer-unavailable also raises an abnormal-summary interrupt and wakes RX tasks. | Medium-high; improves an exhaustion recovery path but can increase interrupt load during sustained starvation. |
| MAC address order | Low address register is written before high. | High address field is written before low, matching ESP-IDF. | Medium; affects perfect unicast filtering and requires repeated boot/reset verification. |
| Diagnostic accessors | No public raw register snapshots. | Two new public tuple-returning diagnostic methods read DMA/MAC state. | Low runtime risk, but inappropriate unplanned API growth for a patch release. |

Normal TX/RX buffer ownership, packet copying, and poll-demand behavior are
otherwise unchanged by the candidate diff.

## Vendor Claim Validation

Detailed source locations and checksums are preserved in
[V0.1.2_VENDOR_REFERENCES.md](vendor/V0.1.2_VENDOR_REFERENCES.md).

| Claim | Result | Basis |
|-------|--------|-------|
| MDIO must use peripheral-controlled output enable. | Validated. | ESP32 TRM output-enable definition, Microchip MDIO read cycle, and ESP-IDF bidirectional SMI setup agree. |
| ESP-IDF resets EMAC after enabling its bus clock and before HAL init. | Validated with qualification. | The values and order match, but ESP-IDF performs both operations inside an RCC atomic section. |
| esp-hal 1.1 `bind_handler` binds and enables at the handler priority on the current core. | Validated. | esp-hal 1.1.1 source performs the vector write and calls `enable`. |
| RBUE is required or RX remains permanently dead until reinitialization. | Not established. | The TRM validates suspension, RBUE, and poll-demand recovery, but also documents retry on a later recognized frame; ESP-IDF's default mask does not enable RBUE. |
| High-then-low MAC programming is the vendor order. | Validated. | ESP-IDF writes the high field before the low register. |
| Low-then-high necessarily races an internal comparator latch. | Not vendor-documented. | Treat this as an inference from hardware observations until a repeatable test captures it. |

## Required Remediation

### 1. Rebuild the Release Branch

- Branch `release/v0.1.2` from the reviewed `main` commit or its current
  fast-forward successor.
- Reapply MDIO, reset, esp-hal, RBUE, and MAC-order changes as separate commits.
- Do not carry merge commits from the old candidate.
- Exclude `rx_debug()` and `mac_debug()` from v0.1.2. If retained for later
  development, redesign them as named snapshot types or explicitly
  feature-gated diagnostics.

### 2. Make Reset Sequencing Safe

- Combine EMAC bus-clock enable and reset into one protected initialization
  transaction.
- Provide exclusion equivalent to ESP-IDF's RCC atomic section across
  interrupts and the ESP32's other core, or document and enforce an equivalent
  invariant in the safe API.
- Ensure the sequence cannot clobber an unrelated in-progress DPORT reset.
- Add a QA test covering initial boot, warm reset, stop/re-init, and repeated
  initialization failure handling.

This is a release blocker because `Emac::init` is safe and unconditional while
the reset register is shared global hardware state.

### 3. Complete esp-hal Feature Wiring

- Forward the crate's `esp32` feature to `esp-hal?/esp32`.
- Enable esp-hal's `unstable` feature whenever this crate's `esp-hal` facade is
  enabled, because the facade publicly uses unstable interrupt types and APIs.
- Confirm the exact feature mapping does not expose experimental `esp32p4`
  support.
- Commit the regenerated root `Cargo.lock`.
- Update app and QA lockfiles if their resolutions change.
- Re-evaluate the narrowly ignored unmaintained-crate advisories in
  `deny.toml`; remove each exception as soon as esp-hal or defmt removes the
  affected transitive dependency.
- Add a CI target check that enables the `esp-hal` facade without relying on an
  example crate to supply missing dependency features.

The reviewed candidate only compiled on target when
`esp-hal/esp32` and `esp-hal/unstable` were supplied manually.

### 4. Prove RBUE Recovery

- Add a deterministic QA mode that withholds RX consumption until every
  descriptor is CPU-owned.
- Verify status shows RBUE and receive state `4`.
- Resume the consumer, verify descriptors are recycled, issue poll demand, and
  demonstrate subsequent unicast receive.
- Count interrupts while the consumer remains blocked and set an acceptable
  upper bound to detect an interrupt storm.
- Repeat with synchronous polling, the async adapter, and embassy-net.
- Rewrite the code comment to state what the TRM proves and separate it from
  observed failure symptoms.

### 5. Prove MAC Filter Programming

- Test at least 20 cold boots and 20 software resets with promiscuous mode
  disabled.
- Verify hardware MAC readback equals the configured address before start.
- Receive broadcast, multicast as configured, and unicast to the device.
- Confirm unicast to a different destination is rejected.
- Repeat after a runtime `set_mac_address`.
- Describe high-then-low as vendor-aligned ordering; do not state the latch
  mechanism as established fact.

### 6. Prove MDIO and PHY Bring-up

- Read BMCR, BMSR, PHYID1, and PHYID2 repeatedly on the canonical WT32-ETH01
  LAN8720A path.
- Confirm reads are neither permanently `0x0000` nor `0xffff`.
- Exercise a write/read sequence on a reversible PHY configuration bit.
- Validate link down, link up, speed, and duplex transitions.
- Preserve any secondary IP101GRI evidence as additional coverage, not as a
  replacement for the canonical LAN8720A test.

### 7. Close Release Metadata Gaps

- Set the crate version and root lockfile package version to `0.1.2`.
- Add a `0.1.2` changelog section that identifies the esp-hal 1.1 minimum and
  the behavior fixes.
- Record the compatibility impact for downstream projects exactly pinning
  esp-hal 1.0.
- Confirm all new public items have documentation and every new `unsafe` block
  has a `// SAFETY:` rationale.
- Complete the version-specific
  [release checklist](V0.1.2_RELEASE_CHECKLIST.md).

## Implementation Order

1. Create `release/v0.1.2` from `main`.
2. Land CI branch coverage and cargo-deny policy.
3. Land the MDIO fix with its QA coverage.
4. Land protected clock-and-reset sequencing with lifecycle QA.
5. Land the esp-hal 1.1 port, feature forwarding, lockfiles, and target CI.
6. Land the MAC write-order fix with filter QA.
7. Land RBUE recovery only after the exhaustion and interrupt-load tests pass.
8. Update version, changelog, release notes, and package metadata.
9. Run the complete release checklist and merge the release branch to `main`.

Each behavior change should remain independently revertible through the release
until hardware QA is complete.

## Merge Gates

The release branch may merge only when all of these are true:

- [ ] All required remediation items above are complete.
- [ ] Every GitHub Actions job passes on the release head.
- [ ] `cargo deny --all-features --locked check` passes with no errors.
- [ ] The standalone esp-hal facade target check passes.
- [ ] WT32-ETH01/LAN8720A hardware QA passes from a cold boot and warm reset.
- [ ] RX exhaustion recovers without an interrupt storm.
- [ ] Non-promiscuous unicast RX passes the repeated boot/reset matrix.
- [ ] Root and app lockfiles are committed and reproducible.
- [ ] The package diff contains no diagnostic accessors unless separately
  approved as public patch-release API.
- [ ] Changelog and release notes accurately state compatibility changes and
  evidence limits.

Contributor hardware logs are useful evidence but are not substitutes for
repeatable repository-owned QA.

---

## Release Contents

The intended v0.1.2 scope is:

- MDIO direction correction.
- Safe EMAC clock/reset sequencing.
- esp-hal 1.1 interrupt binding and complete feature wiring.
- Vendor-aligned primary MAC address programming.
- RBUE-based RX recovery only if its stress gates pass.
- Dependency policy and release documentation.

Public diagnostic APIs and ESP32-P4 work remain outside v0.1.2.
