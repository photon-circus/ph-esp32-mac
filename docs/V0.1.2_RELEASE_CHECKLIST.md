## Hardware Validation

Run the finite suites with the Rust host controller:

```bash
cargo xtask qa run --suite mdio --lab qa/lab.toml
cargo xtask qa matrix --lab qa/lab.toml --cold 20 --warm 20
cargo xtask qa run --suite mac-filter --lab qa/lab.toml
cargo xtask qa run --suite rx-sync --lab qa/lab.toml
cargo xtask qa run --suite rx-async --lab qa/lab.toml
cargo xtask qa run --suite rx-embassy --lab qa/lab.toml
```

- [ ] The tree is clean and evidence is keyed to the exact release SHA.
- [ ] Every bundle contains serial, pcap, normalized JSON, JUnit, metadata,
  firmware and lock hashes, tool versions, reset reasons, and `SHA256SUMS`.
- [ ] No bundle contains `INCOMPLETE` or is marked sandbox-only.
- [ ] Required `SKIP`/`BLOCKED`, missing traffic/interrupts, stale identity,
  reset, timeout, or missing terminal records fail the run.
- [ ] `reset.atomicity` is no longer `BLOCKED`; the protected RCC change and
  scripted-MMIO concurrent-writer regression landed together.

### MDIO on the Canonical Board

- [ ] WT32-ETH01 wiring, LAN8720A reset/address straps, and the external 50 MHz
  RMII clock are verified and recorded.
- [ ] 100 consecutive BMCR/BMSR/PHYID1/PHYID2 samples complete without timeout,
  zero, or `0xffff` results.
- [ ] Every sample reports PHYID1 `0x0007` and
  `PHYID2 & 0xfff0 == 0xc0f0`.
- [ ] Every BMSR sample uses the required double read for latch-low status.
- [ ] The ANAR pause-advertisement bit is toggled, read back, restored, and its
  restored value is verified.
- [ ] The run starts link-up, then a host-controlled link-down/link-up cycle is
  observed with valid speed and duplex after recovery.

### Reset

- [ ] 20 stop/new/init/start cycles succeed in the same static storage slot.
- [ ] Deliberate second initialization is rejected on every applicable cycle.
- [ ] Initialization with the RMII clock missing fails without pre-enabling the
  EMAC clock; retrying with a freshly constructed EMAC after clock restoration
  succeeds.
- [ ] 20 firmware software resets complete and retain exact run identity.
- [ ] 20 relay-controlled cold boots complete and retain exact run identity.
- [ ] A non-promiscuous, sequence-tagged unicast challenge succeeds after every
  software reset and cold boot.
- [ ] MAC, RCC, DMA register, and descriptor readback is recorded and validated
  after every lifecycle cycle.
- [ ] `reset.atomicity` is no longer `BLOCKED`; one private scripted-MMIO
  exclusion scope proves clock-before-reset order, restoration of the original
  reset value, unrelated-bit preservation, and concurrent-writer handling.

### MAC Filter

- [ ] Before start, MACADDR0 matches MAC A exactly (`low=0x12000002`,
  `high=0x80000201`) and promiscuous mode is disabled.
- [ ] Pass-all-multicast is disabled and filter slot 1 contains the configured
  multicast address.
- [ ] At a controlled rate, 32 sequence-tagged frames are injected for each of
  device unicast, broadcast, configured multicast, and alien unicast.
- [ ] Every intended frame is received exactly as tagged and zero alien frames
  are received.
- [ ] After changing A to B, MACADDR0 reads
  `low=0x12000002, high=0x80000301`; B is accepted and A is rejected.

### RX Sync

- [ ] With consumption withheld, all four descriptors fill, zero remain
  DMA-owned, RU is set, the receive state is 4, and RUE+AIE are enabled.
- [ ] During one second with no traffic, no more than two additional RU ISR
  entries occur.
- [ ] During an exact 4096-frame/two-second flood, ISR growth is no greater
  than frames sent plus eight and the firmware heartbeat progresses.
- [ ] Flood completion is acknowledged only after the exact stimulus and
  NIC-drain interval.
- [ ] Draining restores DMA ownership and a tagged sentinel arrives within one
  second without driver reinitialization.

### RX Async

- [ ] The four-descriptor exhaustion, RU/state-4, RUE+AIE, quiet-period, flood,
  interrupt-growth, and heartbeat gates above pass using the actual async ISR
  state and receive future.
- [ ] The recovery frame completes the pending receive without reinit.
- [ ] A second pending receive wakes only when a newly tagged sentinel arrives.

### RX Embassy

- [ ] Executor/network-driver polling is blocked while interrupts remain
  active, reproducing four-descriptor exhaustion with RU and receive state 4.
- [ ] Polling resumes without reinit and fixed-IP UDP echo is observed on wire
  within two seconds with exact run, step, address, and sequence identity.
- [ ] A separate non-promiscuous DHCP run captures a BOOTP-valid Request and
  matching ACK with the same transaction/client identity and a nonzero address.
- [ ] The DHCP ACK address exactly matches the firmware observation.

### Manual Runner Controls

- [ ] `.github/workflows/hardware-qa.yml` exists on `main` through an explicitly
  approved tooling-only merge before `workflow_dispatch` is used.
- [ ] The workflow has no `push`, `pull_request`, or `pull_request_target`
  trigger.
- [ ] The `esp32-lab` environment requires reviewer approval.
- [ ] The selected full SHA is verified as an exact commit on
  `v0.1.2-candidate`.
- [ ] Per-board concurrency and `[self-hosted, esp32, wt32-eth01]` labels are
  configured.
- [ ] The lab runner is dedicated, updated to Actions Runner 2.329.0 or later,
  has no reusable repository/cloud credentials, and cannot reach production
  networks.
- [ ] Checkout and artifact-upload actions are pinned to reviewed immutable
  commit SHAs.
- [ ] The protected environment's `QA_LAB_CONFIG` configuration variable is
  loaded at step execution and resolves outside the checkout.
- [ ] After candidate identity succeeds, evidence upload runs even when a suite
  fails, missing evidence is an error, and all suite outcomes are aggregated.

### Secondary Hardware

- [ ] Any IP101GRI results are labeled as secondary coverage.
- [ ] Secondary-board success is not used to waive WT32-ETH01/LAN8720A gates.
